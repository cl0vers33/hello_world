# 自主实践任务3：手工安装原理说明

> 用自己的话解释 SDK、平台工具链、PATH 三层关系

## 一、三层是什么

### 第一层：Flutter SDK

Flutter SDK 是"核心本体"。它包含三样东西：

1. **Flutter 框架源码**：`packages/flutter/` 目录下那一堆 Dart 代码，提供 MaterialApp、Widget、Scaffold 等基础组件。
2. **flutter 命令行工具**：`bin/flutter` 这个可执行脚本，是我们输入 `flutter create`、`flutter run`、`flutter doctor` 时实际调用的程序。
3. **内置的 Dart SDK**：Flutter 自带一份 Dart，不需要单独装 Dart。`flutter` 命令会自动用它内嵌的 Dart 运行，所以装 Flutter 就等于装了 Dart。

一句话：Flutter SDK 既是源码库，也是工具链，也顺带把 Dart 一起给了。

### 第二层：平台工具链

SDK 只管"写 Dart、编译 Flutter"，但要把应用编成 Android 能装的 APK、Windows 能跑的 exe，还差"把 Dart 编译产物翻译成各平台原生机器码"的工具。这就是平台工具链：

- **Android 端**：Android Studio（含 Android SDK + AVD 模拟器管理）。没有它，Flutter 无法生成 APK，也没有模拟器可跑。装完还要 `flutter doctor --android-licenses` 接受许可。
- **Windows 桌面端**：Visual Studio 勾选"使用 C++ 的桌面开发"工作负载。Flutter 桌面应用最终是 C++ 调 Windows API，所以需要 VS 的 C++ 编译器与 Windows SDK。
- **Web 端**：只要一个 Chrome 或 Edge，Flutter 把 Dart 编译成 JavaScript 跑在浏览器里，不需要额外工具链。

一句话：平台工具链负责"把 Flutter 的中间产物翻译成具体平台能执行的二进制"。

### 第三层：环境变量 PATH

PATH 是操作系统的"找命令的目录表"。把 Flutter SDK 的 `bin` 目录加进 PATH 后，在任意目录敲 `flutter`，系统会沿 PATH 列出的目录依次找 `flutter` 这个可执行文件。

PATH 没配对，会出现 `flutter: command not found`——这是指南第三章"翻车警告"里特意强调的点：改完 PATH 必须重开终端，因为旧终端还记着旧的 PATH。

一句话：PATH 是把 SDK 的命令"暴露"给整个系统的开关。

## 二、三层如何协作

执行 `flutter run -d chrome` 时，背后发生的事：

1. 系统按 PATH 找到 `flutter` 命令（第三层 → 第一层）。
2. `flutter` 命令调用 SDK 内置的 Dart 解释自己（第一层自洽）。
3. 目标是 Chrome，Flutter 把 Dart 编译成 JavaScript，调 Web 工具链（第二层：浏览器即可）。
4. 输出文件落到 `build/web/`，浏览器加载它，界面渲染出来。

如果是 `flutter run -d emulator-5554`：

1. 同样靠 PATH 找到 `flutter`。
2. Flutter 调 Android 工具链（第二层：Android SDK + Gradle + Kotlin 编译器），把 Dart 编译成 ARM/x64 机器码打进 APK。
3. 通过 `adb` 安装到模拟器并启动。

## 三、一句话总结三层关系

> **SDK** 提供"写什么、用什么命令"；**平台工具链**提供"编成什么、跑在哪"；**PATH** 把 SDK 的命令接到任意终端，使三层能在任何地方被一键触发。

## 四、与"翻车警告"对照

| 警告 | 对应层 | 说明 |
|------|--------|------|
| 改完 PATH 必须重开终端 | 第三层 | 旧终端的环境变量是旧的 |
| 解压路径含中文/空格 | 第一层 / 第二层交界 | SDK 安装路径会影响后续 Gradle、CMake 等工具的路径解析 |
| 镜像环境变量两个 URL | 第一层 | 不配镜像，下载 SDK 组件会超时 |
| `flutter doctor` 只报告不开药 | 全层 | doctor 列出问题，但具体装 Studio、VS、接受许可都得自己动手 |
